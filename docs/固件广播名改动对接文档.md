# ESP32-C3 固件改动对接文档：支持 App 修改蓝牙广播名

## 一、需求背景

App 需要在连接 ESP32-C3 后，把用户自定义的蓝牙广播名写入设备，设备收到后**立即修改自己的广播名并重启广播**（类似蓝牙耳机改名）。

当前固件广播名是 `NimBLEDevice::init("洁洁的哈士奇")` 写死的，App 无法修改。

## 二、BLE 协议改动

在**现有 Service 0xF000 下新增一个 Characteristic 0xF002**。现有 0xF001、0x2902 及所有指令协议**完全不变**。

| 项 | 值 |
|------|------|
| Service UUID | `0xF000`（现有，不变） |
| 新增 Characteristic UUID | `0xF002` |
| 属性 | `WRITE`（只需写；建议加 `READ` 方便调试回读） |
| 写入类型 | Write Request（带响应，WRITE_TYPE_DEFAULT） |
| 数据内容 | UTF-8 字符串，即新广播名 |
| 长度限制 | 1 ~ 20 字节 |

## 三、固件行为要求

App 写 0xF002 后，固件需要：

1. 校验：长度 1~20 字节，超出或为空则忽略（不修改）
2. 保存新名字到 NVS（**必须持久化**，断电重启后广播名不丢）
3. 重启 BLE 广播使新名字生效（见下方参考代码）
4. 广播重启后，手机端扫描应能看到新名字

### 参考代码（NimBLE-Arduino）

```cpp
#include <NimBLEDevice.h>
#include <Preferences.h>   // NVS 持久化

Preferences prefs;
NimBLECharacteristic *pNameChar;

void restartAdvertising(const String &newName) {
    NimBLEDevice::stopAdvertising();
    NimBLEDevice::deinit(true);           // 释放 BLE 栈
    NimBLEDevice::init(newName.c_str());  // 用新名字重新初始化
    NimBLEServer *server = NimBLEDevice::createServer();
    // ★ 注意：deinit 后需要重新注册全部 server 回调、service、characteristic
    setupServices(server);                // 重新建 0xF000/0xF001/0xF002
    NimBLEAdvertising *adv = NimBLEDevice::getAdvertising();
    adv->start();
}

class NameCharCallbacks : public NimBLECharacteristicCallbacks {
    void onWrite(NimBLECharacteristic *pChar) override {
        String newName = String(pChar->getValue().c_str());
        newName.trim();
        if (newName.length() == 0 || newName.length() > 20) return;

        // 1) 持久化到 NVS
        prefs.begin("blecfg", false);
        prefs.putString("adv_name", newName);
        prefs.end();

        // 2) 重启广播（延迟一点，先让 write response 发出去）
        //    在回调里直接 deinit 会断开 GATT，可能 response 发不出去
        //    建议置标志位，由 loop() 里延迟 500ms 执行 restartAdvertising
        pendingName = newName;
        nameChangeAtMs = millis();
    }
};
```

**⚠️ 关键坑（务必注意）：**

1. **不要在 onWrite 回调里直接 deinit**——GATT 连接会被立即切断，Write Response 可能发不出去，App 端会报写入失败。正确做法：onWrite 里只存 NVS + 置标志，`loop()` 里检测到标志后 `delay(500)` 再执行重启广播。
2. **deinit 后所有 Service/Characteristic/回调都要重建**，包括新的 0xF002 本身，否则下次改名就没有入口了。
3. 重启广播期间 GATT 断开是**预期行为**，App 端已做自动重连（3 秒），无需固件额外处理。
4. 开机时从 NVS 读名字：`NimBLEDevice::init(prefs.getString("adv_name", "洁洁的哈士奇"))`。

## 四、App 端已实现（无需固件关心，仅供联调参考）

- 保存名字时若已连接且初始化完成 → 立即写 0xF002
- 未连接 → 先存 App 本地，等下次 GATT 连接 + MTU + CCCD 全部就绪后自动下发
- 写入使用 Write Request（带响应），与 0x31/0x30 指令相同的写方式
- 设备重启广播后 App 会自动重连

## 五、联调验收标准

1. App 连接设备 → 弹窗改名 → 保存 → toast 显示"已保存并写入设备"
2. 约 1~2 秒后设备广播名变为新名字（用任意 BLE 扫描工具可验证）
3. 设备断电重启，广播名仍为新名字（NVS 持久化生效）
4. App 内改回默认名"洁洁的哈士奇"同样生效
5. 原有功能（0x31 开充 / 0x30 关充 / 电量阈值）不受影响
